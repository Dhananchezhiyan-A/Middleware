## Scope and Method

The configured database was verified by `getPrisma()`/`assertSafeDatabaseUrl`; the connected database name was `middleware` and the non-production guard requires loopback. `dct_crm`, `dctcrm`, and other databases were not accessed. This assessment describes that local database snapshot only; it does not establish production contents.

Row counts were collected for every public table with a `tenantId` column. Foreign-key relationships between tenant-bearing rows were checked for differing `tenantId` values. No row payloads, passwords, API-key hashes, refresh-token hashes, webhook public IDs, encrypted secrets, or lead payloads were displayed.

Redis DB 0 was inspected using `SCAN MATCH bull:*`, `TYPE`, `HGET` of BullMQ job `data`/`name`, and read-only list/zset membership queries. Payloads were parsed in memory only for tenant labels and referenced-record existence checks; raw payloads were not displayed. The existing development worker was running, so queue counts are a time-specific snapshot and changed during repeated scans.
